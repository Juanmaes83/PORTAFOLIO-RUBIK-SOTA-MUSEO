ARTWORK ATTENTION TRACKING
────────────────────────────────────────

Track how long each artwork is meaningfully viewed.

An artwork is considered actively viewed only when all of the following
conditions are true:

1. The visitor is within the existing interaction distance.
2. The camera is facing the artwork.
3. The conditions remain true continuously for at least 800 milliseconds.
4. The browser tab is visible and active.
5. No project information panel is currently covering the experience.

Start the artwork dwell timer only after these conditions have remained
true for at least 800 milliseconds.

Stop and record the active dwell period when:

- the visitor turns away
- the visitor moves out of range
- another project becomes focused
- a project panel opens
- the browser tab becomes hidden
- the page is closed
- the visitor navigates away

Ignore attention periods shorter than 800 milliseconds.

Do not create a database request on every animation frame.

Accumulate a complete uninterrupted attention period and write one
record when that period ends.

Use a reasonable facing-direction dot-product threshold.

Tune the threshold against the existing museum and artwork positions.

If the facing-direction check proves genuinely unreliable, use a
distance-and-screen-center calculation instead.

If you make that fallback, state clearly in the final report that you
changed the method and explain why.

Do not silently remove the facing requirement.

────────────────────────────────────────
PROJECT PANEL TRACKING
────────────────────────────────────────

Track project information-panel viewing separately.

- Start a panel dwell timer when a project panel opens.
- Stop it when the panel closes.
- Stop it when the browser tab becomes hidden.
- Stop it when the visitor leaves the page.
- Store the record with source: "panel".
- Do not create duplicate records for one uninterrupted panel visit.
- Ignore accidental panel visits shorter than 800 milliseconds.

Use navigator.sendBeacon or fetch with keepalive where appropriate so
the final dwell period can still be recorded when the page closes.

Do not block or delay the interface while an analytics record is being sent.

Analytics failures must never prevent the project panel from opening
or closing.

API

Implement:

POST /api/inspections

Accept:

- projectId
- sessionId
- dwellMs
- source
- startedAt, if required by the implementation

Validate all incoming data on the server.

Validation requirements:

- projectId must match an existing project from content.ts
- sessionId must be a valid UUID
- source must be exactly "artwork" or "panel"
- dwellMs must be a positive integer
- reject values shorter than the accepted minimum
- reject clearly unreasonable dwell values
- reject missing or malformed payloads
- do not trust client-provided values without validation

Return clear JSON responses for:

- successful creation
- invalid project
- invalid session
- invalid dwell duration
- invalid source
- malformed request
- internal database failure

Do not return database credentials or internal stack traces to the browser.

Implement:

GET /api/stats

Return aggregate statistics for every existing project:

- projectId
- totalArtworkDwellMs
- totalPanelDwellMs
- totalDwellMs
- inspectionCount
- uniqueSessions

Also return:

- mostViewedProjectId

Determine the most-viewed project primarily by totalDwellMs.

Use inspectionCount only as a tie-breaker.

If no genuine analytics records exist, return:

- empty or zeroed statistics
- mostViewedProjectId: null

Do not invent a winner when no records exist.
